## Candidates

- footer and badge remainder: from the M014 review. See "shortcode edge cases". A DOI with Markdown emphasis (`10.5281/*zenodo*.1`) gives a badge for `10.5281/zenodo.1`, while `CITATION.cff` holds the raw text. `license: "MIT"` or `zenodo: "x"` (text where a map belongs) renders an empty footer or no badge, while `write_citation()` raises `supplement_error_field_type`. Unquoted `code: 1.0` shows "1" linked to spdx.org/licenses/1.html. A site that keeps the old footer (`[{{< supplement-license code >}}](…LICENSE.md)`) and copies in the new extension gets a link inside a link. An id that SPDX lists but the footer's table of 8 does not, written in another letter case (`apache-1.1`), may link to a missing page if spdx.org paths depend on case (not checked). The `supplement-download` link joins a two-paragraph `zenodo.archive-url` into one address. — added 2026-10-19
- Windows check: run the template tests and a render on Windows (CI or by hand), including the no-R test, which skips there, and `nojekyll.ts` with a `C:\` output path. From the M003 review. Also from the M004 review: data files of 2 GiB or more may read as missing (32-bit `ftell` in Windows Lua), and the 1 GB sparse size fixture may cost 1 GB of disk off macOS when Quarto copies it into `docs/`. Also from the M006 review: `create_supplement()` path handling on Windows (a broken link or junction at a template path, where `Sys.readlink()` returns `""`, and trailing separators). — added 2026-10-18
- shortcode edge cases: from the M004 review. `file` values are read as Markdown, so read the raw value or encode it (names with `%`, `#`, `--`, `_x_` break). A `data` map instead of a list renders nothing, and bare strings give `not found: ''`. A path outside the project or an absolute path renders but is not published. A `{{< meta >}}` value that names an existing path is rewritten on subfolder pages, and a description written as `../data` shows as `data` there. A fresh site has an empty paragraph under "Archived Version". `quarto-required: ">=1.4.0"` is untested below 1.10. From the M014 plan: the footer cannot see backslash escapes or HTML entities in a license id, or an unquoted number or `yes` in a license value (these render while `write_citation()` refuses them), and the badge reads `--`, `'`, or a non-breaking space in a DOI suffix after Markdown changes it, so these can still disagree with `write_citation()`. Narrowed 2026-10-19 by M014 (`supplement-license` now stops unless it has one argument, `code` or `content`). — added 2026-10-18
- docs site and walkthrough: a package site built with the toolkit itself, plus a first-time guide to GitHub Pages and Zenodo. Its `_pkgdown.yml` reference index lists `write_citation()` and `write_zenodo()` (from the M005 review). — added 2026-10-18
- paper figure files: the model reports write the paper figures with ggsave to `analyses/*.pdf` and `analyses/*.png`, which `.gitignore` blocks, so the site does not publish them. Decide if the template gives figures a tracked, published folder. From the M001 review. — added 2026-10-18 — started M017
- Windows-safe names: from the M007 review. add_report() accepts names that Windows reserves, such as `con`, and add_data() accepts base names that end in `.`, which Windows strips. `is_link()` reads `Sys.readlink()`, which returns `""` for a junction, so a junction `data/` or `analyses/` is not refused (see "Windows check"). — added 2026-10-18
- web link check: `check_supplement()` tests only links inside `docs/`. Also request each web address on the site's pages, which needs a network and can fail when a site is down. From the M008 plan. — added 2026-10-18
- stale stored output: `check_supplement()` finds reports with code but no stored output in `_freeze/`. Also find stored output that is older than its report source, from the source hash in each `execute-results/html.json`. From the M008 plan. — added 2026-10-18
- link check false positives: from the M008 review. `check_supplement()` does not decode `&amp;` or `&#38;` in a link, so `R&D.csv` reads as broken. It reads `href` text in HTML comments, in `<code>` text, and in `data-href` attributes, and it does not trim spaces around a value. It skips pages in hidden folders of `docs/`, and a symlink in `docs/` to a file outside the repository passes. It reads no upper-case `HREF=` or `SRC=`, `src = "…"` in `<script>` text gives a false row, and `data-src=` and `xlink:href=` also match. A symlink loop in `docs/` repeats a page's rows once per loop level. Each fix changes the link check's criterion, so plan it as a milestone. — added 2026-10-18
- stored output chunk shapes: from the M008 review. The `no-stored-output` check misses chunks written ```` ``` {r} ````, chunks inside a `>` blockquote, `{R}`, and reports with only inline `r` code, and a four-backtick block that shows ```` ```{r} ```` as text gives a false row. See also "stale stored output". — added 2026-10-18
- release check edge cases: from the M008 review. A file in Git LFS reads as its full size in the large-file check, a large or `.rds` file committed earlier and since deleted is not seen though a push still sends it, and a second Zenodo badge on the home page (for a related dataset) gives a `doi-mismatch` row. A large file that is staged and then deleted from disk gives no row, and a `docs/` folder with no `index.html` (one report rendered by name) gives no `not-rendered` row. A report that `.gitignore` blocks still gets a `no-stored-output` row, a UTF-16 `CITATION.cff` is judged though GitHub reads only UTF-8, and on a Mac without developer tools `git --version` may open an install dialog (not confirmed). — added 2026-10-18
- release during a merge: from the M015 plan. The printed `git commit -m "Release vX.Y.Z" -- .` is a partial commit, which git refuses while a merge is in progress, so a release run during an unfinished merge stops at that command. — added 2026-10-19
- release pathspec edge cases: from the M015 review. See "release during a merge". `git commit -- .` also stops during a cherry-pick or revert with a conflict. A site folder that git ignores, with files added by force, makes `git add -A -- .` exit 1, and the new `CITATION.cff` and `.zenodo.json` are not committed (as before). Running the add and commit again with nothing changed exits 1 and lists files outside the site. Windows PowerShell may drop the `--` (not checked; harmless if so). — added 2026-10-19
- release edge cases: from the M009 review. A tab before the colon (`version\t: "1.0.0"`) is valid YAML, but `release_supplement()` stops with `supplement_error_no_version`, and its hint invites a second `version:` key. A CR-only `_supplement.yml` reads as one line, so its `version:` line reads as missing (see "YAML insert edge shapes"). A flow map `supplement: {version: …}` gets a hint to add a line at the indent of `paper-title:`, which a flow map does not have. A linked `_supplement.yml` is written through its link, while linked outputs are refused. When the only row is the exempt `CITATION.cff` DOI row, `check_supplement()` prints "1 problem found" and the release then goes ahead. A full disk during a standalone `write_citation(overwrite = TRUE)` or `write_zenodo(overwrite = TRUE)` leaves the old file truncated, with no restore. A tagged or anchored value (`version: !!str 1.2.3`) gets a message that says there is no `version:` value. The link refusal for `CITATION.cff` and `.zenodo.json` reads `is_link()`, which misses a Windows junction (see "Windows-safe names"). A `bump` with invalid UTF-8 gives the right error and also a base warning from `grepl(perl = TRUE)` in `is_version()` (RR01 finding 5.2). The folder check in `read_outputs()` uses `file.access()`, which may misfire on Windows or network drives, and its test skips Windows. On macOS `file.exists()` ignores letter case, so a lowercase `citation.cff` is read and replaced as the output. — added 2026-10-18
- template test flake: during M009, one `devtools::test()` run failed 3 times at `test-template.R:140` (`git check-ignore` printed output where none was expected), and five later runs passed. Find the cause. — added 2026-10-18
- release snapshot remainder: from the M011 review. See "release edge cases". A save to `_supplement.yml` after `check_unchanged()` reads it again and before the release writes it is still lost with no message (the help page says so). `_supplement.yml` is never refused as a link, so a link put in its place during the check, to a file with the same bytes, is written through. When an output becomes a link or a file that cannot be read during the check, the `supplement_error_file_exists` or `supplement_error_write` message does not say that `_supplement.yml` also changed (a folder now joins those two cases). Narrowed 2026-10-18 by M012 (one read before the check, and a folder at an output refused before and after it). — added 2026-10-18
- release write order remainder: from the M012 review. See "release snapshot remainder". An interrupt after the last write returns and before the restore guard is marked done still puts back all three files, with no warning. An error inside the put-back after a failed write leaves the guard unmarked, so the put-back runs again on exit and warns "The release was interrupted", the wrong word for an error (as before M012). The release and the writers parse `_supplement.yml` in two ways (`yaml.load()` on lines with a final line break added, and `yaml.load()` on the text that `read_yaml()` would read, with no final line break; corrected M016): a block scalar at the end of a file with no final line break, or a `|+` block, reads with extra line breaks on the release side, and `clean_space()` in `value()` is what keeps the output bytes equal. No test covers such a file, and the parser's line number for an error at the end of the file differs between the two. — added 2026-10-18
- parse error edge cases: from the M016 review. See "release write order remainder". `read_supplement()` reads a `_supplement.yml` that is not UTF-8 only up to the bad byte, with a warning, so `write_citation()`, `write_zenodo()`, and `check_supplement()` judge the cut text (a run gave `supplement_error_authors`), while `release_supplement()` and `add_data()` give `supplement_error_encoding` (as before M016). With `options(warn = 2)`, a yaml warning such as the one for `!!float abc` becomes `supplement_error_parse`. `read_supplement()` keeps the incomplete-final-line warning of `read_yaml()`, which the release read does not give. — added 2026-10-19
