## Candidates

- Build a package site with pkgdown: a package site built with the toolkit itself. Its `_pkgdown.yml` reference index lists `write_citation()` and `write_zenodo()` (from the M005 review), `write_dockerfile()` (from the M032 review), and `check_tools()` (from M037). — added 2026-10-18, split 2026-10-19
- Split the template guide by reader: from the ease-of-use review. `README.md` and `inst/template/_README.md` put edge cases, such as Windows device names, the SPDX id syntax, and `--` read as an en dash, beside the main steps. The first render makes the template guide the site repository's `README.md`, so visitors on GitHub read author instructions under a placeholder citation. A short guide for the main steps, the edge cases in help pages or a reference part, and a public README for the site's readers would fix both. The first-time walk now lives in `vignettes/publishing.Rmd` (M038, corrected 2026-10-23). — added 2026-10-22 — started M050
- Shorten the setup code in new reports: from the ease-of-use review. `add_report()` writes about 50 lines, about 30 of them the Computing environment block that hides the home folder with regular expressions. The example report has 123 lines, and the template guide asks authors to copy `save_png()` by hand. Package functions for that code would shorten reports, but a render by name would then need supplement installed, which is a design choice. The `save-figure` chunk grew with the link stop and the PNG end check (M046). — added 2026-10-22
- Check web links on the rendered site: web link check: `check_supplement()` tests only links inside `docs/`. Also request each web address on the site's pages, which needs a network and can fail when a site is down. From the M008 plan. — added 2026-10-18
- Handle short folder names on Windows: Windows short folder names: from the M018 review. Quarto 1.10 run on Windows from a folder whose path holds an 8.3 short name (such as `RUNNER~1` in a temporary folder) does not find the figures that knitr writes, so `docs/` lacks `example_files/` and the page links a missing figure; `check_supplement()` reports it as a broken link. The tests avoid it by running Quarto from `normalizePath()` of the folder (`long_dir()`). The R help examples use `tempdir()`, which can hold such a name. A fix could be a note in the README or a hint in the broken-link row. — added 2026-10-19
- Measure the cost of large data files: Windows large data files: from the M018 review. Quarto copies each file the data table links into `docs/`, the size fixtures included (seen on macOS, where the 2 GiB copy stays sparse at 4 KB); the disk cost of the 1 GB, 2 GiB, and 4 GiB fixtures on Linux and Windows was not measured. On Windows the data table counts the bytes of each file of 2 GiB or more on every render, and the time for a 4 GiB file was not measured. — added 2026-10-19
- Add a test coverage report to CI: coverage report: add the usethis test-coverage workflow, which runs `covr` and uploads to Codecov, beside the check workflow. It needs the repo linked in a Codecov account, and coverage never gates a merge. From the M018 plan. — added 2026-10-19
- Show output on failed status checks: status check output: from the M019 plan. The status checks without `info =` in `test-shortcodes.R`, `test-release-supplement.R`, and `test-check-supplement.R` do not show the command's output when they fail (`grep -nE '\$status' tests/testthat/*.R` lists them; `test-add-render.R`, `test-create-supplement.R`, and some lines in the others already pass `info =`). `expect_status()` in `helper-template.R` is the M019 form for them. `git_run()` drops stderr, and the shortcode test runners return only stderr. — added 2026-10-19
- Settle the env argument of run_in: run_in env argument: from the M020 review. No caller passes `env` to `run_in()` in `helper-template.R` since M018 moved the no-R test to `withr::with_envvar()`, and on Windows `system2()` passes `env` only to commands such as R. Remove the argument, or make it set variables through withr. — added 2026-10-19
- Resolve page links against a base tag: from the M021 review. `check_supplement()` reads the `href` of a `<base>` element as a link and resolves every other link on that page against the page's own folder, while a browser resolves them against the `<base href>` value. The `a01b723` pattern did the same. — added 2026-10-20
- Close the link reader's browser gaps: from the M021 review. `tag_links()` reads some markup differently from a browser: a comment does not end at `--!>`, so a link after it is missed; `</` followed by a non-letter (`</ foo <a href="x">`) is not a bogus comment; and a script holding `<!--` and `<script>` ends at its first `</script>`. The help page of `check_supplement()` lists the last case. See also "Resolve page links against a base tag". — added 2026-10-20
- Read huge script bodies past PCRE limits: from the M021 review. PCRE's match limit counts the steps of one match, so a script, style, textarea, or title body that holds about 5 million `<` (a page of 20 MB or more, such as a large htmlwidget with HTML in its cells), a comment of millions of `-`, or a tag with millions of attributes gives `check_supplement()` a row saying the page cannot be read, which stops `release_supplement()`. Finding each such element's end tag with separate `gregexpr()` calls and an R loop would avoid the limit. See also "Close the link reader's browser gaps". — added 2026-10-20
- Read odd-named folders on Windows: from the M022 review. On Windows, `check_supplement()` does not enter a folder in `docs/` that `is_link()` counts as a link though it is not one (a name that ends in a space or `.`, or a path over 260 characters), so the pages in it are not read and give no row. A page link to a file link whose target is missing passes there, because `file.exists()` is TRUE for it; since M045 `is_link()` finds such a link through fs, so `docs_entries()` lists it as a link and the `ignored-output` check leaves it out, but no Windows test pins either, and whether the page-link check still passes it was not checked (M045 review). — added 2026-10-20
- Check how Pages publishes links in docs: from the M022 review. `check_supplement()` gives no row for a symbolic link whose target is inside `docs/`, but git stores an absolute target (`/Users/me/site/docs/x.csv`) as written, so it points nowhere on GitHub. It gives a row for a relative link to a repository file outside `docs/`, which a Pages build may still publish (`actions/upload-pages-artifact` runs `tar --dereference`; the template's branch deploy was not checked). Whether git on Windows commits a junction's contents was not checked. Pages in `docs/.git/` or `docs/.github/` are now read, though Pages does not publish them. — added 2026-10-20
- Speed up the path test of page links: from the M022 review. Once `docs/` holds any link, `link_ok()` runs `file.exists()` and `normalizePath()` on each part of each page link. 200 pages with 100 links each took 2.49 s with no link in `docs/` and 3.28 s with one (macOS, measured by the review on 2026-10-20); Windows was not measured. — added 2026-10-20
- Match menu items only on plain text: from the M025 review. `yaml_scalar()` in `R/yaml-insert.R` reads a one-item flow sequence as its item, so `text: [Analyses]` in `_quarto.yml` matches the Analyses step of `add_report()`. Reading it with `yaml_load_list()` would make it a list and no match, and would keep the `eval.expr = FALSE` setting in one place. — added 2026-10-20
- Record the Python setup of reports: from the M030 plan. The Computing environment section and the renv and Docker layers (M030 to M032) cover R reports only, and `check_tools()` (M037) does not look for Python or Jupyter. A Python report could print its Python and package versions, and a site could keep a `requirements.txt` or `uv.lock`. — added 2026-10-21
- Compare renv.lock with report records: from the M031 plan. `renv.lock` shows the packages at the last snapshot, and each report that has a Computing environment section shows those of its own last render, so the two can disagree. `check_supplement()` could give a row when a report's stored output names a package version other than the lockfile's. — added 2026-10-21
- Log render retries after a cache lock: from the M033 review. `run_in()` and `run_split()` in `helper-template.R` run a Quarto render once more when it fails with "database is locked" from Quarto's Sass cache, and keep no record of it, so a rise in such locks under parallel tests shows only when two in a row fail a test. A message or a count in the test output would show how often it happens. See also "template test flake". — added 2026-10-21

- Report broken Quarto links on Windows: from the M037 review. - Match folder names across Unicode forms: from the M042 review. `check_leftover_output()` in `R/check-supplement.R` compares the names in `analyses/` with the folders in `_freeze/analyses/` as stored, so a report name and its folder that differ only in composed or decomposed Unicode form give a `leftover-output` row that tells the author to delete live output; the help page states it.
