## Candidates

- [high] template test flake: during M009, one `devtools::test()` run failed 3 times at `test-template.R:140` (`git check-ignore` printed output where none was expected), and five later runs passed. During M017, one run failed in "setup keeps both files when README.md and SUPPLEMENT.md exist" (`quarto render` exited 1), and two later runs passed. Find the cause. — added 2026-10-18 — started M019
- docs site and walkthrough: a package site built with the toolkit itself, plus a first-time guide to GitHub Pages and Zenodo. Its `_pkgdown.yml` reference index lists `write_citation()` and `write_zenodo()` (from the M005 review). — added 2026-10-18
- Windows-safe names: from the M007 review. add_report() accepts names that Windows reserves, such as `con`, and add_data() accepts base names that end in `.`, which Windows strips. Narrowed 2026-10-19 by M018, which made `is_link()` find junctions. — added 2026-10-18
- web link check: `check_supplement()` tests only links inside `docs/`. Also request each web address on the site's pages, which needs a network and can fail when a site is down. From the M008 plan. — added 2026-10-18
- stale stored output: `check_supplement()` finds reports with code but no stored output in `_freeze/`. Also find stored output that is older than its report source, from the source hash in each `execute-results/html.json`. From the M008 plan. — added 2026-10-18
- link check false positives: from the M008 review. `check_supplement()` does not decode `&amp;` or `&#38;` in a link, so `R&D.csv` reads as broken. It reads `href` text in HTML comments, in `<code>` text, and in `data-href` attributes, and it does not trim spaces around a value. It skips pages in hidden folders of `docs/`, and a symlink in `docs/` to a file outside the repository passes. It reads no upper-case `HREF=` or `SRC=`, `src = "…"` in `<script>` text gives a false row, and `data-src=` and `xlink:href=` also match. A symlink loop in `docs/` repeats a page's rows once per loop level. Each fix changes the link check's criterion, so plan it as a milestone. — added 2026-10-18
- stored output chunk shapes: from the M008 review. The `no-stored-output` check misses chunks written ```` ``` {r} ````, chunks inside a `>` blockquote, `{R}`, and reports with only inline `r` code, and a four-backtick block that shows ```` ```{r} ```` as text gives a false row. See also "stale stored output". — added 2026-10-18
- release pathspec edge cases: from the M015 review. See "release during a merge". `git commit -- .` also stops during a cherry-pick or revert with a conflict. A site folder that git ignores, with files added by force, makes `git add -A -- .` exit 1, and the new `CITATION.cff` and `.zenodo.json` are not committed (as before). Running the add and commit again with nothing changed exits 1 and lists files outside the site. Windows PowerShell may drop the `--` (not checked; harmless if so). — added 2026-10-19; absorbs release during a merge (the printed `git commit -m "Release vX.Y.Z" -- .` is a partial commit, which git refuses while a merge is in progress, so a release run during an unfinished merge stops at that command), added 2026-10-19 — M015 plan
- figures folder edge cases: from the M017 review. Under freeze, a clone where `figures/` was never committed renders with no `docs/figures/`, and `check_supplement()` finds no problem, because no page links a figure. The `create_supplement()` message says to render once before the first commit, but that render writes `figures/bootstrap-means.png` and no `docs/figures/`. Setup ends `.gitignore` with `!docs/` and `!_freeze/` only, so an existing `figures/` or `*.png` rule keeps `figures/` out of git. The `analyses/*.png` and `analyses/*.pdf` rules match lower case only on Linux (the README says so; bracket patterns as for `.rds` would fix it). The example's `png()` has no `on.exit(dev.off())`, so a failed chunk can leave a partial file in `figures/`. With `execute-dir: project`, `file.path("..", "figures")` writes outside the site. `dir.create(showWarnings = FALSE)` hides a file named `figures`. — added 2026-10-19
- Windows file links: from the M018 implement. On Windows a file symbolic link to a missing file reads as a file that exists, with `file.access()` 0 and `normalizePath()` giving the link's own path, so `is_link()` misses it and `release_supplement()` stops with "Could not read" (`supplement_error_write`) in place of the link refusal; that stop comes in `read_outputs()`, before the writes, and no Windows test checks that nothing is written. The test "a link to a missing output file is refused before any write" skips on Windows for it. A fix needs a check outside base R's file functions, such as `dir /AL`. Making such a link needs admin rights or developer mode. From the M018 review: the same rule counts as a link any name that the folder lists but `file.exists()` cannot read, such as a name that ends in a space or `.` or a path over 260 characters. — added 2026-10-19
- Windows short folder names: from the M018 review. Quarto 1.10 run on Windows from a folder whose path holds an 8.3 short name (such as `RUNNER~1` in a temporary folder) does not find the figures that knitr writes, so `docs/` lacks `example_files/` and the page links a missing figure; `check_supplement()` reports it as a broken link. The tests avoid it by running Quarto from `normalizePath()` of the folder (`long_dir()`). The R help examples use `tempdir()`, which can hold such a name. A fix could be a note in the README or a hint in the broken-link row. — added 2026-10-19
- Windows large data files: from the M018 review. Quarto copies each file the data table links into `docs/`, the size fixtures included (seen on macOS, where the 2 GiB copy stays sparse at 4 KB); the disk cost of the 1 GB, 2 GiB, and 4 GiB fixtures on Linux and Windows was not measured. On Windows the data table counts the bytes of each file of 2 GiB or more on every render, and the time for a 4 GiB file was not measured. — added 2026-10-19
- coverage report: add the usethis test-coverage workflow, which runs `covr` and uploads to Codecov, beside the check workflow. It needs the repo linked in a Codecov account, and coverage never gates a merge. From the M018 plan. — added 2026-10-19
- status check output: from the M019 plan. Status checks in `test-shortcodes.R`, `test-release-supplement.R`, `test-check-supplement.R`, `test-create-supplement.R`, and `test-add-render.R` do not show the command's output when they fail. `git_run()` drops stderr, and the shortcode test runners return only stderr. — added 2026-10-19
- [low] Suggests floor guard: nothing stops a new test from calling a testthat function newer than the DESCRIPTION floor, and the withr, knitr, and rmarkdown entries in Suggests have no floor. A CI job on the floor versions, or a test that compares the functions the tests call with the floor's exports, would catch it. From the M013 plan. — added 2026-10-18
