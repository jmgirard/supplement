## 1. Cause of each defect return

| Return | Criterion | Cause | Short form |
|---|---|---|---|
| 1 | AC3 | (c), exposing a small (b) | The test asserted the check name, not the count, in the skipped-only case |
| 2 | AC5 | (a) | "For any reason" and "each file it made" quantify over the filesystem and over every step |
| 3 | AC2 | (b), licensed by (a) | A real code defect (`$` under `perl = TRUE`), found by a probe outside the test list because "any other `bump`" invited one |
| 4 | AC2 | (d): the criterion scripts the test at the literal level | The code and the test are right; the test's literals differ from the criterion's |

**Return 1 (AC3).** AC3 was bounded: it says the error "gives the number of problems" whenever `skipped` is not empty or a non-exempt row exists. The implementation had two message shapes and the skipped-only shape left out the count (work log, line 80). The test that covered the skipped-only case asserted the check name only; T6 changed it so "the skipped-checks test now asserts the number in both cases" (line 82). The criterion stated the rule and the test did not check it, so the cause is (c); the code slip it uncovered is (b) and was a two-line change.

**Return 2 (AC5).** AC5 reads: "If any step after the `_supplement.yml` write stops, for any reason, the function puts back the old bytes of each file it changed, removes each file it made, and stops." Its named procedure is three mocks (two failing writes and an empty `citation`). The two findings that floored the return were a dangling-link `CITATION.cff` whose target lies outside the site (pass 2 diff-bug #1) and a failure while printing (diff-bug #11). Neither is in the test list; both are inside the promise as written, because "each file it made" ranges over the whole filesystem and "any step" ranges over printing. That is (a). The printing case also has a (b) component: the implementer read "any step" as "any write" and left `report_release()` outside the guard (line 132). T7 then added six more probes (line 86), which is the usual signature of an open-domain criterion: the probe list grows after each pass instead of being fixed before the first.

**Return 3 (AC2).** `is_version()` ended with `$`, which under `perl = TRUE` matches before a final `\n`, so `release_supplement("1.2.3\n")` wrote `version: "1.2.3\n"` (pass 3 blame-history #2, line 148). That is a genuine (b): a user could hit it from a shell wrapper that passes a line-terminated value. The test list for AC2 at the time listed no whitespace form, so the listed probes all passed; the reviewer went outside the list because AC2 promised `supplement_error_argument` "for any other `bump`". So the defect is (b), and the mechanism that found it is (a).

**Return 4 (AC2 after the re-plan).** The criteria audit on the re-cut wrote five literal strings into AC2's test clause (line 95: "probes needed more end forms and an inner line break"). T8, done the same day, added the same five shapes with `1.2.4` in place of `1.2.3` (line 101; test file line 118). `check_bump()` refuses both sets (the pass-4 reviewer ran AC2's values, line 186; I ran them too). The code is right and the test checks the property the criterion names. The only mismatch is between two literal strings. In letter this is (c), but the root cause is (d): a criterion that carries exact test inputs can be failed by an equivalent test, and the review's "fails as written" rule has no room to call the two equivalent.

**The pattern.** One return of four was a defect that reaches users (return 3). One was a real restore gap that no listed probe could have found (return 2, the link case). Two were letter-versus-letter mismatches between the criterion and the test (returns 1 and 4). Three of the four came from criteria that either quantify over an open domain ("any", "for any reason", "each file") or script the test at the string level. Each review pass spawns three hunting agents and reads the criteria fresh; an open-domain criterion gives each new reader a new reading, and the floor-return rule turns any one finding that fits the reading into a return. The Review section shows the cost: pass 2 recorded 19 findings, pass 3 recorded 20, pass 4 recorded 7, and each pass's fix-now list became the next pass's new surface (T7 added a test for each of its fixes; T9 made nine changes; pass 4 then found diff-bug #2 and #3 in T9's own additions). The returns are not evidence that the design is wrong (see question 3); they are evidence that the stop condition is undefined.

## 2. AC2, AC3, AC5 as written

**AC2.** The accept side is bounded by a stated rule: one non-NA string equal to a word or whose whole text, with no character before or after, matches the AC1 form. "Stops with `supplement_error_argument` for any other `bump`" is the complement of that rule, so it is checkable against the code (one predicate in `check_bump()`, `R/release-supplement.R:198-199`) even though no test can enumerate it. The test clause is bounded by a list. The one open spot is the list of five literal strings, which the test must then carry verbatim. Two ways to close it; either is enough:

- Keep the literals and make the test use them exactly (a one-line change at `tests/testthat/test-release-supplement.R:118`). Cheapest.
- Or replace the literal list with the shapes: "The test also expects `supplement_error_argument` for a version followed by a line break, a space, or CRLF, preceded by a space or a line break, and split by a line break inside it, and reads a current version written as `"1.2.3\n"` in double quotes as `1.2.3`." Then any concrete strings of those shapes satisfy it.

**AC3.** Bounded. The stop condition is a rule over the result (`skipped` not empty, or a row other than the `CITATION.cff` doi-mismatch row), the message content is a rule ("gives the number of problems"), the no-version case is defined by indent and line shape, and the test clause names each case plus the byte comparison. The return against it was a test that did not check the stated rule, not an open promise. No change needed.

**AC5.** Open in three places: "any step after the `_supplement.yml` write", "for any reason", and "each file it changed, removes each file it made". The first two make printing and interrupts part of the promise without naming them; the third makes the promise range over any path a write can reach, which is how a link target outside the site became a failing case. Narrower wording that keeps what the user gets and that the existing tests already settle:

> AC5: The function then writes `CITATION.cff` and `.zenodo.json` with `overwrite = TRUE`, and both hold the new version. Before the first write it refuses, with no file changed, a `CITATION.cff` or `.zenodo.json` that is a link, or that it cannot read or write. If the write of `CITATION.cff` or `.zenodo.json`, or the printing of the commands, signals an error or an interrupt, the function writes the old bytes back to each of `_supplement.yml`, `CITATION.cff`, and `.zenodo.json` whose bytes differ from the bytes it read before the release, removes `CITATION.cff` or `.zenodo.json` when it did not exist before the release, and stops with `supplement_error_release_write` (or, after an interrupt, warns) naming any file it could not put back. A test reads both files after a release; mocks a failing write of `CITATION.cff` and of `.zenodo.json`, each with the files present and absent; mocks a write that only warns; uses an empty `citation`; mocks a failure in the printing; and interrupts in `write_zenodo()`. It links each output to a present and to a missing target, and makes each output unreadable and unwritable. Each time it finds the three files, and the file list of the site, as they were before, and no file outside the site made.

This names the three paths, the three steps, and the two signals, and it lists every probe the branch already has. Anything not on that list is a candidate row by construction, not a return.

## 3. The restore design

The design in `write_release_files()` (`R/release-supplement.R:300-367`) and `read_outputs()` (`:157-188`) is: snapshot the bytes of the three files, write `_supplement.yml` (through `write_checked()`, which itself puts the old bytes back on a failed write, `R/yaml-insert.R:55-84`), call the two writers, print, and on any error or interrupt put back each file whose bytes differ and remove each file that did not exist. The snapshot-and-compare restore is byte-faithful, idempotent (the `on.exit` and the error handler can both run it), and the D-011 re-read check in front of it guards the one edit that is not a plain overwrite. I found no path by which it corrupts a file (question 5 lists what I tried). It is sound.

Its cost is structural, and it explains the shape of the findings. `write_citation()` and `write_zenodo()` take a `path` and read `_supplement.yml` from disk (`R/write-citation.R:81-83`, `R/write-zenodo.R:45-47`), so every semantic check inside them (missing `citation`, a bad DOI, a folder in the way) runs only after `_supplement.yml` has been written and must be undone. That is where pass 2 diff-bug #7, the empty-`citation` probe, pass 3 diff-bug #3, and pass 4 diff-bug #2 come from: each is a case "found only after `_supplement.yml` is written". `read_outputs()` is the response: a growing pre-write check that re-implements, for two paths, what the writers will check again. The second cost is that printing sits inside the guard, so a success line can be followed by a rollback (pass 3 diff-bug #1 is the message that this produced).

**Alternative A: build every new byte in memory, check every target, then write.** Split each writer into a builder that takes the `supplement` map and returns the file text (the code from `require_fields()` to `yaml::as.yaml()` or `jsonlite`, already a pure function of `meta` apart from the final `write_utf8()`), and a thin exported wrapper that reads, builds, and writes. `release_supplement()` then reads `meta`, sets `version` to the new value, builds both texts, runs `check_overwrite()` on both targets, and only then writes three files. Semantic failures become pre-write refusals with no restore; the domain of "a step after the first write stops" shrinks to I/O errors and interrupts, which the byte-restore handles already. Size: about 40 lines moved across `R/write-citation.R`, `R/write-zenodo.R`, and `R/release-supplement.R`, plus the empty-`citation` test changing from "is put back" to "is refused before any write". It removes a class of findings for the future. It does not remove any finding the branch has not already fixed and tested, so it buys nothing toward the next review, and it changes two files that M009's scope does not name. Record it as a candidate row; do not re-cut for it.

**Alternative B: temporary files and rename.** `file.rename()` is atomic for one file on one POSIX filesystem, not across three files, so the rollback stays. On Windows it fails when the target exists, which needs remove-then-rename and reopens the window. A rename over a link replaces the link instead of writing through it, which changes the behaviour the pass-3 diff-bug #4 row describes. An interrupt leaves a temporary file in the site that `git add -A` would stage. More edge cases, no fewer. Reject.

**Printing inside the guard.** The question of whether a failure while printing should undo a correct release is a criterion question, not a design one: AC5 as written demands it, return 2 enforced it, and the test at `test-release-supplement.R:458-466` pins it. The files are the product and the commands are derivable from the version, so the stronger design prints nothing that claims success until `done` is set and leaves printing outside the guard. Changing this now means revisiting a decision the maintainer accepted at return 2; the narrowed AC5 above keeps the current behaviour because the cheapest passing path is to leave green tests alone. Flagging the disagreement rather than working around it: I think the rollback-after-success-line window (`:346` to `:365`) is the wrong trade, but it is small and not worth a fifth round.

## 5. Defects the four passes did not record

**5.1 An edit to `_supplement.yml` made while `check_supplement()` runs is lost.** `R/release-supplement.R:118` reads the lines and bytes of `_supplement.yml`, `:142` runs `check_supplement()` (which renders nothing but can take seconds on a large `docs/`), and `:343` writes the lines from `:118`. An author who saves `_supplement.yml` in the gap gets the pre-check text back with only the version changed, and no message. Confirmed with `check_supplement()` mocked to change `paper-title` on disk: after `release_supplement("patch")` the file holds the old `paper-title` and the new version. This is the `_supplement.yml` half of pass 3 diff-bug #10, which recorded the outputs' snapshot gap only; the outputs' half is undone by a restore, this half overwrites a saved edit. Fix (about four lines): after `check_release_problems()`, re-read the file's bytes and stop with `supplement_error_yaml` (or a new class) when they differ from `read$bytes`; or move `:117-137` below `:143` and drop the `calls$n == 0L` assertions that depend on the order. Not inside any criterion; candidate row.

**5.2 A `bump` with invalid UTF-8 gives the right error and a stray base warning.** `is_version()` at `R/supplement-yml.R:299` calls `grepl(perl = TRUE)`, which warns "input string 1 is invalid UTF-8" before returning `FALSE`. `release_supplement("1.2.3\xff")` stops with `supplement_error_argument` as AC2 asks, and also emits that warning. Harmless for users, but `expect_error()` reports a warning in testthat 3e if such a value is ever added to the probe list. Fix: `validUTF8(x) & grepl(...)` or `suppressWarnings()` around the `grepl()`. Cosmetic; candidate row.

**5.3 A completed release can be undone by an interrupt between the guard and `done <- TRUE`.** `R/release-supplement.R:341-365`: `report()` prints the success line inside the `tryCatch`; `done <- TRUE` is at `:365`. An interrupt that lands after the `tryCatch` returns and before `:365` runs the `on.exit` restore, which puts all three files back without a warning (the put-back succeeds). The window is a few instructions wide and I could not hit it by hand; it is a logical gap, not a reproducible one. It is a consequence of AC5's demand that printing be inside the guard (question 3). No action for M009.

Nothing else. What I tried and found correct: a multi-line double-quoted value whose continuation line looks like `version: x"` (the scanner picks the wrong line, the D-011 re-read refuses with `supplement_error_yaml`, no write); `"1.2.3"#c` with no space before the comment (refused with the line to add); a quoted key `"version":`; a comment with quotes after the value; a plain value with spaces before its comment; a `supplement:` line with a trailing comment; a trailing slash on `path`; a latin1-marked `bump`; a `bump` with names; a version part longer than R's integers on both sides of the comparison; a duplicate `version:` key (the yaml package refuses it before any package code runs); a tab-indented key (the parser's own error, as the Errors section says).

## Beyond the brief

- The review process spends most of its findings outside the criteria. Across passes 2 to 4 the Review section records 46 findings (counting pass 4's five already-filed prior-review items as one): 4 floored returns, 19 were fix-now, 13 went to candidate rows, and 10 were rejected. The fix-now items are what each later pass re-reviews, so each pass's surface is partly the previous pass's fixes (pass 4 diff-bug #2 and #3 are in T9's additions). A review that files fix-now items as a batch for one follow-up round, rather than requiring them before the next pass of the same milestone, would have ended M009 at pass 3.
- `cairn/DESIGN.md` Architecture says `release_supplement()` "refuses a `CITATION.cff` or `.zenodo.json` that is a link or cannot be read or written"; after the pass-4 diff-bug #2 fix it will also refuse a folder it cannot write into. Add the words then, or the next claim audit will.
- The `release_supplement()` help page (`R/release-supplement.R:60-65`) says "When it stops, no file is changed, unless a file that changed cannot be put back." Finding 5.1 is a case where it stops nowhere and a file changes beyond the version line. If the fix in 5.1 lands, the sentence holds; if the row waits, the help should say that `_supplement.yml` is read before the checks run.
- `is_version()` is used both for `bump` and for the current version. The current version goes through `clean_space()` first (`R/supplement-yml.R:102`), `bump` does not. That asymmetry is correct per AC1 and AC2 as written (a file value is trimmed, an argument is not), but it is the kind of thing a future reader will "fix". A one-line comment at `check_bump()` saying that `bump` is deliberately not trimmed would save a round.

## Recommendations

1. **apply** Fix the three owed items (question 4, items 1 to 3) in one implement round; no re-cut, no split.
2. **apply** In the same round, replace AC5 with the bounded wording in question 2 and make AC2's test clause and the test agree verbatim (or switch AC2's clause to shapes). Record in the work log that the amendment lists the probes already on the branch.
3. **apply** Give the next review a disposition rule in its handoff: a finding floors a return only if a listed test or a stated rule of a criterion fails on it; everything else is fix-now or a candidate row. Write the rule into `cairn/LESSONS.md` so it outlives M009.
4. **apply** File finding 5.1 (the `_supplement.yml` snapshot gap) as its own candidate row, cross-referenced to pass 3 diff-bug #10, with the four-line fix noted. It is the one unrecorded behaviour that loses user data, and it should not wait inside the "release edge cases" bundle.
5. **consider** A candidate row for alternative A in question 3 (builders that take `meta`, so semantic checks run before the first write). It simplifies `read_outputs()` and future writers, and it is the right shape if a third output file ever arrives. Not for M009.
6. **consider** Move the success line and the command printing outside the restore guard, with AC5 narrowed to the three writes. This removes finding 5.3 and pass 3 diff-bug #1's message. It reverses a return-2 decision, so it is the maintainer's call; I would take it in the same follow-up as recommendation 5, not now.
7. **consider** Treat fix-now findings from a review pass as one batch for a follow-up round rather than a precondition of the next pass of the same milestone, when none of them fails a criterion. This is a process change for the plugin's rulebook, outside this repository's files.
8. **reject** Temporary files and rename (alternative B): atomicity does not extend across three files, Windows rename semantics reopen the window, and a stray temporary file is a new edge case that `git add -A` would stage.
9. **reject** Splitting the milestone or starting a fresh branch from main: every task is done and tested on the branch, the gate has passed on four passes, and the returns trace to the criteria's wording and the review's stop rule, not to the branch's design (work log, line 98, named that as the falsifier, and it did not come true).
10. **reject** Raising the testthat floor as part of this round: the `local_mocked_bindings()` row already holds it, and the brief says a dependency change needs separate approval.
