## Goal

Windows CI keeps a trace of each crash of a test process, and the timed tests pass at Windows speed.

## Scope

**In:** A Windows-only step of `.github/workflows/R-CMD-check.yaml` builds a crash catcher DLL before the check, and each Windows CI test process loads it so that a crash writes a dump. A step after the check reads each dump, prints where the crash happened, and uploads the dumps. Each Windows CI test process logs each test it starts, so a dump can be matched to the last test that started. A `workflow_dispatch` input plants a crash, to show the steps work. A reference page records the two crashes seen so far. One test helper gives Windows 5 times the time bound of each timed test.

**Out:** Finding and fixing the cause of the crash. This waits for a dump, which comes in about 1 of 200 Windows jobs, and lives in the new parked row "Read the next Windows crash dump". A loop that tries to cause the crash now (declined at the plan question set). Speeding up the generated-pages test, which has no time bound (no row: it takes time and fails nothing). The Sass lock rows "Measure Sass lock reruns on Windows" and "Log render retries after a cache lock", which stay as they are.

## Acceptance criteria

- [x] AC1: On windows-latest, `.github/workflows/R-CMD-check.yaml` builds a crash catcher DLL before the check step. A helper in `tests/testthat/helper-*.R` loads it on Windows CI when the workflow sets the variables that name the DLL and the dump folder. The catcher's handler, on exception code 0xC0000005 or another fatal code it lists, writes a minidump of its own process into the dump folder with MiniDumpWriteDump, at most 3 times per process, and then lets the exception go on. It names each dump `<program>.<pid>.<n>.dmp`. A step after the check runs whether the check passed or failed. For each `.dmp` file in the dump folder that holds an exception record, it prints the program name, the process id, the exception code, and the module that holds the fault address, with the offset into that module. If no loaded module holds the address, it prints the address and a note that no module holds it. For any other `.dmp` file, it prints its name and that it holds no exception record or could not be read. If the folder holds no `.dmp` file, the step prints one line that says so.
- [x] AC2: In a Windows CI run, each test process writes the file and the name of each test into a log named by its process id, before the test starts. For each dump whose process id matches a log, the AC1 step prints that log's last line. For any other dump, it prints that no log matches.
- [x] AC3: If the dump folder holds a `.dmp` file, the job uploads the folder as an artifact.
- [x] AC4: `cairn/references/windows-test-crash.md` lists each crash that a search finds. The search reads the logs of every attempt of the windows-latest job of R-CMD-check runs from 2026-10-19 to 2026-10-29 that failed, for exit code -1073741819. Each entry gives the run, the attempt, the job, the date, the commit, the test file, and the R, testthat, callr, and processx versions. The page states how many job attempts the search read, and `cairn/references/INDEX.md` carries its line.
- [x] AC5: Each line that `grep -n 'system.time(' tests/testthat/*.R` lists stores a time that its test compares with a bound from one helper in `tests/testthat/helper-*.R`. On Windows the helper returns 5 times the bound a test passes it, and on other systems it returns that bound unchanged.
- [ ] AC6: `devtools::test()` is clean on macOS, and the three R-CMD-check jobs pass on the PR head.
