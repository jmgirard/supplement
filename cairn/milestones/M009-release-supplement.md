## Goal

Export `release_supplement()`, which raises the site version in `_supplement.yml` after `check_supplement()` finds no problem and prints the commands that make the release.

## Scope

**In:** A `version` field in the template's `_supplement.yml`, which `write_citation()` and `write_zenodo()` write. `release_supplement(bump, path = ".")` runs `check_supplement()`, raises the version, writes `CITATION.cff` and `.zenodo.json` again, and prints the git and GitHub commands for the author to run. It runs none of them. Tests, a help page, README, `_README.md`, NEWS, and DESIGN text.

**Out:**
- The checks themselves: M008.
- A release date in `CITATION.cff` (`date-released`): not planned. Add a candidate row if it is needed.
- Calls to the GitHub or Zenodo API: out of scope for version 1 (DESIGN Purpose & Scope).

## Acceptance criteria

- [x] AC1: The template's `_supplement.yml` has `version: ""` under `supplement:`, with a comment. `write_citation()` writes `version` to `CITATION.cff`, and `write_zenodo()` writes `version` to `.zenodo.json`, with the value of `supplement.version` when it is not empty. The value is read with the spaces and line breaks at its start and end removed, as for every `_supplement.yml` value. Both leave the field out when it is empty. Both stop with `supplement_error_version` for a value that is not three whole numbers joined by `.`, each `0` or without a leading zero. A test writes `1.0.0` and `0.10.2` to both files and reads them back, and it fires the error for `1.0`, `v1.0.0`, `01.0.0`, `1.0.0-rc1`, and `1. 0.0`.
- [x] AC2: `release_supplement(bump, path = ".")` accepts `bump` only when it is one non-NA string that equals `"patch"`, `"minor"`, or `"major"`, or whose whole text, with no character before or after, is a version in the AC1 form. A word raises that part of the current version by 1 and sets the parts after it to 0. The current version is the AC1 value, and an empty one counts as `0.0.0`. A version in `bump` must be greater than the current version, part by part as numbers. It stops with `supplement_error_argument` for any other `bump`, with `supplement_error_version` for a version that is not greater or a current version not in the AC1 form, and with `supplement_error_field_type` for a current version that YAML reads as anything other than text, such as an unquoted `1.10`, `true`, or a list. A test checks: `1.2.3` with each word, `0.9.9` with `"major"` (`1.0.0`), `1.9.0` with `"minor"` (`1.10.0`), an empty version with `"patch"` (`0.0.1`), `1.2.3` with `"1.10.0"` (accepted), and `1.2.3` with `"1.2.3"` and `"1.2.2"` (refused). The test also expects `supplement_error_argument` for `"1.2.3\n"`, `"1.2.3 "`, `"1.2.3\r\n"`, `" 1.2.3"`, and `"1.2\n.3"`, and reads a current version written as `"1.2.3\n"` in double quotes as `1.2.3`.
- [x] AC3: Before it writes, the function runs `check_supplement()`. It stops with `supplement_error_release_check`, and gives the number of problems, when the result's `skipped` attribute is not empty or the result has a row other than a `"doi-mismatch"` row for `CITATION.cff`, which the release writes again. When `_supplement.yml` has no `version:` key with a one-line value at the child indent of the block-style `supplement:` map, it stops with `supplement_error_no_version` and shows the line to add by hand. A test fires each error, and a release that only a `CITATION.cff` DOI row would block, and finds the file list and the bytes of every file in the site the same after each error.
- [x] AC4: The function changes only the value on that `version:` line and writes the new value in double quotes. A byte comparison finds every other byte of `_supplement.yml` the same. Before the write, the yaml package reads the changed text, and the function stops unless the result is the old map with the new version. A test uses the template's file, a file with a comment after the value, a file with CRLF line endings, a single-quoted value, and an unquoted value.
- [ ] AC5: The function then writes `CITATION.cff` and `.zenodo.json` with `overwrite = TRUE`, and both hold the new version. If `write_citation()`, `write_zenodo()`, or the printing of the commands signals an error, or an interrupt is signaled when `write_zenodo()` is called, the function writes the old bytes back to each of `_supplement.yml`, `CITATION.cff`, and `.zenodo.json` whose bytes differ from the bytes it read before the release, except a file whose write-back itself fails, removes `CITATION.cff` or `.zenodo.json` when it did not exist before the release, and stops. A test reads both files after a release. It then mocks a failing write of `CITATION.cff` and of `.zenodo.json`, each with both files present and with both absent, uses an empty `citation`, which stops `write_zenodo()`, mocks a failure in the printing, and signals an interrupt in place of `write_zenodo()`. After each of these failing probes, it finds the three files, and the file list of the site, as they were before.
- [x] AC6: The function prints, and returns invisibly as a character vector, the commands for version `X.Y.Z`: `git status`, `git add -A`, `git commit -m "Release vX.Y.Z"`, `git tag vX.Y.Z`, `git push`, `git push origin vX.Y.Z`, and `gh release create vX.Y.Z --generate-notes`. `git add -A` adds the files that `check_supplement()` checked, so `docs/` and `_freeze/` reach the tagged commit. It also prints that, after Zenodo archives the release, the author adds the new version DOI to `_supplement.yml` and renders the site again. `R/release-supplement.R` does not call M008's git helper, so the function starts git only through `check_supplement()`, which M008's AC3 search covers.
- [x] AC7: The package README and the template's `_README.md` describe `release_supplement()` and the `version` field. Its help page has an example in `\dontrun{}`, because the function needs a rendered site in a git repository. NEWS.md has an entry for the function and the field.
