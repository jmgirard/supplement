# M008: check_supplement() lists release problems

**Status:** done (2026-10-18, PR #8 https://github.com/jmgirard/supplement/pull/8)

**Goal:** Export `check_supplement()`, which lists the problems in a site that would break or leak a release.

**Outcome:** `R/check-supplement.R` exports `check_supplement(path = ".")`. It changes no file and returns, invisibly, a data frame (`check`, `file`, `problem`) with a `skipped` attribute, and prints each problem. Checks: `large-file` (over 104,857,600 bytes, symbolic links not counted) and `saved-object` (`.rds`, `.rda`, `.rdata`, `.qs`, `.qs2`, any case) over the files that `git ls-files -z --cached --others --exclude-standard` lists; `no-stored-output` for a report directly in `analyses/` with an R, Python, or Julia chunk and no non-hidden file in `_freeze/analyses/<name>/execute-results/`; `not-rendered` for a missing `docs/`; `broken-link` for quoted relative `href`/`src` values in `docs/**/*.html` that miss a file or a folder with `index.html` (path parts matched by exact letter case, split before percent decoding, a trailing `/` must reach a folder), and for pages that cannot be read; `doi-mismatch` for `CITATION.cff` and badge DOIs that differ from `_supplement.yml`, are not DOIs, or sit in an unreadable `CITATION.cff`. Git runs only through `git_run()` (`--version`, `rev-parse`, `ls-files`); when it cannot run, the git checks are skipped with the reason. Pages and `CITATION.cff` are read through `read_page_text()` (NUL bytes dropped, invalid UTF-8 shown as `<xx>`). `drop_trailing_sep()` in `R/supplement-yml.R` now serves `create_supplement()`, `add_data()`, and the check. README, `_README.md`, NEWS, the help page, and DESIGN.md describe it.

**Decisions:** none cross-cutting. Milestone-local: a regular expression over quoted attributes in place of an HTML parser (no new dependency); the git sweep includes untracked files that git does not ignore; bad DOIs outside `_supplement.yml` give rows, not errors; tabs and line breaks are dropped from link values, as browsers do.

**Review:** three passes, three fresh reviewers each, and three claim audits (64, 51, and 52 claims; 6, 5, and 4 corrected, one of them a regression in reading `CITATION.cff`). Two defect returns: a non-ASCII link and a `[` in the site path (pass 1), and a dangling or unreadable report (pass 2). Of 73 findings, 38 were fixed on the branch, 13 rejected, and 22 sent to candidate rows: "link check false positives", "stored output chunk shapes", "release check edge cases", "YAML parse errors", "testthat floor", and "badge DOI form". The "release checks" row narrowed to `release_supplement()` (M009).
