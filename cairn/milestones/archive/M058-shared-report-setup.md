# M058: Share report setup code through one site file

**Status:** done (2026-10-26, PR #59 https://github.com/jmgirard/supplement/pull/59)

**Goal:** Reports that `add_report()` writes, and the template's example report, get `save_png()` and the Computing environment output from one shared site file, `_scripts/report.R`.

**Outcome:** The template ships `inst/template/_scripts/report.R`, which defines `save_png()` (the `figures` link and file stops of M046, checked on `file.path(site, "figures")` for any `dir`, then the PNG `IEND` check) and `print_environment()` (the M030 home-folder masking). The example's `site` chunk and each `add_report()` report's end with `source(file.path(site, "_scripts", "report.R"), local = TRUE)`, so `local = TRUE` lets the functions see `site` where the chunk runs. The example's `save-figure` and `session-info` chunks only call the two functions. A new report has 40 lines (62 before). `add_report()` copies the template's file when the site lacks it, makes `_scripts/` when missing, never replaces an existing file, refuses a `_scripts` that is a file or link and a `report.R` that is a folder or link (`supplement_error_file_exists`), removes what it made after a failed write, and says to commit the copy. GUIDE.md has a "Shared report code" section (commit the file; `check_supplement()` hashes only the report, so a change to the file gives no stale-output row; render each report by name). The `add_report()` help, NEWS.md, `_README.md`, `_gitignore`, and DESIGN.md describe the file. Tests: the `save_png()` and home-folder tests run against the shared file, plus a `quarto use template` render, a render by name of an `add_report()` report, the copy, keep, four refusal, and rollback cases, and a caller-`dir` link test.

**Decisions:** D-028 (reports share setup code through a site file, not package functions), chosen by the user at the plan over package functions and over shorter inline code.
