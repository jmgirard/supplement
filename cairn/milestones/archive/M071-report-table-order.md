# M071: List reports in menu order on the home page

**Status:** done (2026-10-28, PR #72 https://github.com/jmgirard/supplement/pull/72)

**Goal:** Make the home page's report table list reports in the order of the Analyses menu, through an `order` field that the template's example report and `add_report()` write.

**Outcome:** The template's `analyses/example.qmd` has `order: 1`; Quarto 1.10.19's default listing sort puts reports with a numeric `order` first, by that value, and the others after them by title, so `index.qmd` keeps its listing settings. `next_report_order()` in `R/add-report.R` reads each report that `analysis_reports()` lists through `report_front_matter()` (factored out of `engine_is_knitr()` in `R/check-supplement.R`), with a leading UTF-8 BOM dropped. It counts an `order` that the yaml package reads as one finite number below 1000000 in absolute value. `report_lines()` writes `order: <floor(max) + 1>` (`sprintf("%.0f")`), `order: 1` when no other report exists, and no `order` when other reports exist and none has one, so older sites keep title order. `example_versions` lists the new example's hash under the name `current`, which the next change of the file renames by its squash commit (no fixture added). The `add_report()` help, `GUIDE.md`, the `index.qmd` comment, `README.md`, `NEWS.md`, and `DESIGN.md` state the rule. The demo's table now reads Sample Description, Main Analysis, Robustness Checks, its menu's order.

**Decisions:** none promoted. The plan chose an `order` field over an explicit file list in the listing (a list hides a report added by hand), and writing no `order` on sites whose reports have none over always writing one (the new report would list first).
