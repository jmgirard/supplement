# M035: The writers refuse links and repeated lockfile keys

**Status:** done (2026-10-22, PR #36 https://github.com/jmgirard/supplement/pull/36)

**Goal:** `write_citation()`, `write_zenodo()`, and `write_dockerfile()` refuse a link at an output path by one shared rule, whatever `overwrite` is, and `write_dockerfile()` refuses a `renv.lock` that repeats a key it reads.

**Outcome:** `check_overwrite(files, overwrite, fn)` in `R/supplement-yml.R` takes one or more paths and refuses, in order, a link at any of them, a folder at any of them, then an existing file when `overwrite` is not `TRUE`, all `supplement_error_file_exists`. Its link message says "is a link, so the file is not written there" and "Remove the link, then run `<fn>()` again", with no `overwrite` hint. `write_dockerfile()` calls it once with both targets in place of its own link loop, so a link at `.dockerignore` is reported before a plain `Dockerfile`. `read_lockfile_versions()` refuses a repeated `R` or `Packages` (top level), `Version` in `R`, `renv` in `Packages`, or `Version` in that entry with `supplement_error_lockfile`, before any value check. The Errors sections of `?write_citation` (inherited by `?write_zenodo`) and `?write_dockerfile`, two NEWS bullets, and DESIGN.md Architecture and the "Release edge cases" Known issue state the rules and the Windows exception (a file link to a missing file is not seen as a link). Tests: one link test over 2 writers × 2 `overwrite` values × 4 link shapes (it replaces "a dangling link with the output file's name is kept"), a `.dockerignore` link case, the repeated-key test with a key it does not read, and `expect_link_message()` in `helper-files.R`. All link tests skip Windows.

**Decisions:** none cross-cutting. The plan chose one rule in `check_overwrite()` over a check in each writer, and limited the repeated-key check to the five keys read. The package is unreleased, so the changed errors took no deprecation cycle.
