# M045: Detect broken file links on Windows

**Status:** done (2026-10-23, PR #46 https://github.com/jmgirard/supplement/pull/46)

**Goal:** On Windows, `is_link()` counts a file symbolic link whose target is missing as a link, so the link refusals that read it refuse such a link as they do on macOS and Linux.

**Outcome:** fs joins Imports (D-022). On Windows, `is_link()` in `R/supplement-yml.R` also ORs in `fs_link()`, which calls `fs::is_link()` through the wrapper `fs_is_link()` on `path.expand()`ed, `enc2utf8()`ed paths that are valid UTF-8, once for the whole vector and, if that stops, once per path, an error giving FALSE. `is_reparse_point()` is unchanged. So `release_supplement()`, `write_citation()`, `write_zenodo()`, and `write_dockerfile()` refuse a file link to a missing file on Windows; `add_data()`, `add_report()`, `create_supplement()`, and `check_supplement()`'s link, large-file, and figure checks also read the new answer there. `symlink_or_skip()` moved to `helper-files.R`; the release missing-link test and the two writer link tests run on Windows, folder links as junctions. Two new tests: `is_link()` cases, and a mocked fs error (whole call and one path). Roxygen, man pages, NEWS.md, and DESIGN.md drop the Windows exception.

**Decisions:** D-022 (fs imported; the user chose it over a base R inference from `file.info()`, on the condition that fs is light: 1.05 MB, imports `methods`, needs R 4.1). `check_tools()` kept out at the question set. A Windows CI probe (run 40025299259) confirmed fs before the code was written.
