# M024: check_supplement() finds code chunks in more shapes

**Status:** done (2026-10-20, PR #25 https://github.com/jmgirard/supplement/pull/25)

**Goal:** `check_supplement()` gives a `no-stored-output` row for the code chunk shapes and the inline R code that it now misses.

**Outcome:** `check_stored_output()` in `R/check-supplement.R` reads a chunk start with `chunk_start`, a pattern that follows knitr's chunk pattern and Quarto's chunk scan. The pattern takes any mix of spaces, tabs, and `>`, then three or more backticks and optional spaces or tabs. Then it takes `{r`, `{python`, or `{julia` in any letter case, a space, comma, or `}`, and a line that ends at `}`. A line such as `{r} x` no longer counts. A report with no chunk counts when it has one-line inline `` `r x` `` code and `engine_is_knitr()` finds a top-level `engine: knitr` in its own front matter. The front matter is read with `yaml_read_lines()`, and `yaml_load_list()` in `R/yaml-insert.R` now passes `eval.expr = FALSE`, so no read runs `!expr` code under `options(yaml.eval.expr = TRUE)`. A four-backtick block that shows a chunk, and a chunk in an HTML comment, keep their rows, because knitr 1.52 runs both. The help item states the rules and their limits (`r#` inline code, a `knitr` key, `execute: engine`, includes, `_metadata.yml`, an indented `---`). NEWS changed. The tests add four tests in `test-check-supplement.R`.

**Decisions:** milestone-local: follow knitr's and Quarto's chunk patterns over the old rule plus three fixes (falsified by a Quarto version whose chunk scan differs from knitr's pattern). Inline code counts only under `engine: knitr` in the report's front matter, by the user's answer at the plan (falsified by a common setup that turns on knitr with no chunk and no `engine` key).
