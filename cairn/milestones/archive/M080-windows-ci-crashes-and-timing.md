# M080: Catch Windows test crashes and fix time bounds

**Status:** done (2026-10-30, PR #81 https://github.com/jmgirard/supplement/pull/81)

**Goal:** Windows CI keeps a trace of each crash of a test process, and the timed tests pass at Windows speed.

**Outcome:** The Windows job of `R-CMD-check.yaml` builds `.github/scripts/crash-catcher.c` with `R CMD SHLIB`. `tests/testthat/helper-test-log.R` loads it in each test process on Windows CI and, through a testthat state inspector, writes each test a process starts to `<pid>.log`. The catcher's vectored exception handler writes a minidump with `MiniDumpWriteDump` on an access violation or four other fatal codes, at most 3 per process, and lets the exception go on. After the check, `.github/scripts/read-dumps.py` (standard-library Python) prints each dump's program, process id, exception code, fault module and offset with the nearest export, a stack scan, and the last test of that process; the job uploads the dumps and logs as `crash-dumps`. The job now stops at 60 minutes, since an in-process dump can deadlock. A manual run's `plant_crash` input builds `.github/scripts/plant-crash.c`, and `tests/testthat/test-plant-crash.R` crashes its process (it skips otherwise). `time_bound()` in `tests/testthat/helper-files.R` gives Windows 5 times the 10 s bound of the four timed tests in `test-check-supplement.R`. `cairn/references/windows-test-crash.md` records the two earlier crashes (runs 40310323002 and 40661210581, in `test-create-supplement.R` and `test-renv.R`) from a search of 57 Windows job attempts. The cause stays unknown until the next crash.

**Decisions:** D-040 (crash catcher, test log, plant input, and the Windows time bound; extends D-020). The plan used Windows Error Reporting `LocalDumps`, which wrote no dump for a planted crash; AC1 was amended to the in-process catcher at the user's choice.
