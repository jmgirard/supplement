# M023: add_report() and add_data() refuse names that Windows cannot use

**Status:** done (2026-10-20, PR #24 https://github.com/jmgirard/supplement/pull/24)

**Goal:** `add_report()` and `add_data()` refuse file names that Windows cannot use: device names such as `con`, and data file names that end in `.`.

**Outcome:** `windows_reserved()` in `R/add-utils.R` is TRUE for the 22 ASCII device names on Microsoft's "Naming Files, Paths, and Namespaces" page (`CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, `LPT1` to `LPT9`; COM0 and LPT0 are not on it), in any letter case. `add_report()` stops with `supplement_error_report_name` after its name check. `add_data()` stops with `supplement_error_file_name` after its Markdown name check, for a base name that ends in `.` and for a stem (the part before the first `.`) that is a device name, so `con.csv` and `NUL.tar.gz` are refused. Both messages name Windows. Both checks run before any write and before the file-exists and ignored-type checks. The help pages, NEWS, the template `_README.md`, the `_supplement.yml` comment, and DESIGN.md state the rules. Tests run all 176 letter-case spellings, with accepted controls (`console`, `com10`, `com0`, `x.con`); the `add_data()` refusals skip on Windows, which cannot make such files, and the controls run there first.

**Decisions:** milestone-local: the existing error classes, not a new Windows class (falsified by a caller that must tell the refusals apart); Microsoft's list without COM0 and LPT0 (falsified by a Windows version that refuses a file named `com0`). No D-entry.
