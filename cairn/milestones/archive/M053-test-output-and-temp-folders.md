# M053: Keep test writes in temp folders and show failed command output

**Status:** done (2026-10-24, PR #54 https://github.com/jmgirard/supplement/pull/54)

**Goal:** Three test fixes: the renv render test keeps renv's writes in temporary folders, the linked-output release test fails CI when it cannot make its link, and the status checks that pass no `info` show the command's output when they fail.

**Outcome:** `command_failure()` in `tests/testthat/helper-template.R` now prints `stdout` and `stderr` when a result has no `output`, so `expect_status()` and `expect_command_fails()` show what a `run_split()` result printed and a `git_run()` result's raw `stdout` as text, with nul bytes dropped (testthat 3.3.2's `expect()` builds the message even when the check passes, and `rawToChar()` stops on a nul). The 26 status checks without `info` or `label` in `test-shortcodes.R`, `test-release-supplement.R`, and `test-check-supplement.R` go through those helpers, and the shortcode page builders keep `stdout`. "a value error comes before the refusal of a linked output" makes its link with `symlink_or_skip()`, whose skip reason `.github/scripts/check-skips.R` lists, so a failed link fails CI. The new test "a failed status check shows the output of run_split() and git_run()" in `test-template.R` covers the new printing. DESIGN.md's exit-status sentence names the three files. The renv part was dropped at the user's choice: the render in `test-renv.R` starts no R process, so renv never activates in it, and a local run left the user's renv folder unchanged. No NEWS entry: tests only.
