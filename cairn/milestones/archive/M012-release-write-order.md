# M012: release_supplement() checks every value before it writes a file

**Status:** done (2026-10-18, PR #13 https://github.com/jmgirard/supplement/pull/13)

**Goal:** `release_supplement()` builds the text of `CITATION.cff` and `.zenodo.json` in memory, so that a value or a folder that would stop either writer stops the release before it writes any file.

**Outcome:** `write_citation()` and `write_zenodo()` split into the internal builders `citation_text(meta, call)` and `zenodo_text(meta, call)` plus the exported wrappers; their tests pass unchanged, and an error names the function the user called. `read_supplement()` split into `supplement_file()` and `supplement_map()`; `yaml_parse_lines(lines, label)` keeps the parser's error and names the file through `error.label`. The release reads `_supplement.yml` once with `read_text_lines()`, takes the version and the changed lines from that read, and builds both texts from the changed lines before `read_outputs()` and `check_supplement()`, so the writers' value errors reach the caller with their own class and message. `read_outputs()` refuses a folder with `supplement_error_file_exists`, before the check and at M011's re-read. `write_release_files()` writes the built texts with `write_utf8()` inside the restore guard and lost its `report` argument; `report_release()` runs after the guard, so a print error or interrupt keeps the release. The help page gained the stop order and a writer-classes bullet; NEWS.md, README.md, the template `_README.md`, and DESIGN.md were updated. Tests: the five AC2 values, a byte comparison with the standalone writers over LF, CRLF, and BOM sites with `probe_values`, folder cases before and during the check, print error and interrupt, and the failed write of each of the three files.

**Decisions:** none promoted. At the plan gate the user chose to keep the written files when printing fails, and to change the error class with no deprecation period.

**Review:** full criteria audit at plan (9 findings, fixed), claim audit at implement (32 claims, 9 corrected), one review pass with four lenses (diff-bug, blame-history, prior-review, ripple), 15 findings: 3 fixed on the branch (a folder test that read its state lazily, the parser error's file name, the write error's call), 7 follow-up, 5 rejected. No returns, no amendments. `R CMD check` 0/0/0. Graduated "release write order"; narrowed "release snapshot remainder" and "footer and badge edge cases"; new row "release write order remainder".
