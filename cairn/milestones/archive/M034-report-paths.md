# M034: Reports find the site folder from any folder

**Status:** done (2026-10-22, PR #35 https://github.com/jmgirard/supplement/pull/35)

**Goal:** The example report and each report from `add_report()` find the site folder by one rule, in a render and when their code runs by hand from `analyses/` or from the site folder.

**Outcome:** `inst/template/analyses/example.qmd` has a "Site Folder" section and one `site` chunk before `data`: `QUARTO_PROJECT_DIR` if not empty, else `Find()` over `"."` then `".."` for the folder holding `_quarto.yml`, else `stop("Run this code from the site folder or from its analyses/ folder.")`. The `data` and `save-figure` chunks use that `site` and no longer set it. `site_chunk()` in `R/add-report.R` copies the chunk, fence to fence, from the installed example as the first chunk of each new report (`example_lines()` now also serves `environment_section()`), and the stub's text says to read data as `file.path(site, "data", "<file name>")`. The `add_report()` help page, the site README ("Paper figures" shows the chunk's code; fit files are read as `file.path(site, "analyses", "fits", ...)`), NEWS.md, and DESIGN.md state the rule. Tests in `test-template.R`: the chunk in eight setups (unset and `""`, `.` before `..` in a nested site, a set path, the stop), a full render of an `add_report()` report reading `data/example.csv` in two new sites (one per `execute-dir`), and the README block against the chunk; the M028 hand-run tests run the `site` chunk first. `test-add-report.R` checks the stub's first chunk and text.

**Decisions:** none cross-cutting. At the plan the user chose the `_quarto.yml` lookup over the old `..` fallback and over `execute-dir: project`; the plan chose one `site` chunk over repeating the lookup in each chunk, so a chunk copied alone no longer finds the site.
