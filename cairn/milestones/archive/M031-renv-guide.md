# M031: An author can record and restore a site's R packages with renv

**Status:** done (2026-10-22, PR #33 https://github.com/jmgirard/supplement/pull/33)

**Goal:** The template guide shows how to record and restore a site's R packages with renv, and tests show that a site set up with renv still renders, checks, and commits as before.

**Outcome:** `inst/template/_README.md` has the part "Recording R packages with renv" after "Rendering on the machine with the private data": `renv::init()` once (commit `renv.lock`, `.Rprofile`, and `renv/`; `renv/.gitignore` keeps `renv/library/` out; `install.packages()` in R started in the folder installs into `renv/library/`), `renv::snapshot()` after a render (add `renv.lock` to the private-data recipe's `git add`), and `renv::restore()` on another machine before a render by name. It says a full render runs no R when every report holds stored output, and that `renv.lock` and each report's Computing environment section can differ. README.md points to it and names it in the guide's topics; one NEWS bullet. supplement never calls renv. renv joins Suggests, and `.github/scripts/check-skips.R` counts both renv skip texts as a missing tool (D-021). `renv_site()` in `helper-template.R` builds a rendered, committed `git_site()`, checks renv, knitr, rmarkdown, and sessioninfo for R_HOME's Rscript (one `missing:` line each), and runs `renv::init()` in that Rscript with `--no-init-file`, renv's root and sandbox in `long_dir()` temp folders, sandbox locking off, the four renv path and profile variables unset, and `RENV_VERBOSE=TRUE`. `test-renv.R` has `r_process_lines()` (the `[execProcess]` lines with a word whose base name, ignoring case, quotes, and `.exe`/`.bat`/`.cmd`, is R, Rscript, or Rterm, lookup lines exempt), a probe test of 13 R-call forms and 11 other lines, and one test of a debug-log render with no R line, zero `check_supplement()` rows, and no `renv/library/` path among git's untracked files.
