# M068: Handle renv lockfile edge cases

**Status:** done (2026-10-28, PR #69 https://github.com/jmgirard/supplement/pull/69)

**Goal:** The lockfile readers of `write_dockerfile()` and `check_supplement(renv_lock = TRUE)` handle three cases from the M066 and M067 reviews: a byte order mark, a path under another letter case, and a profile name that `RENV_PROFILE` and `renv/profile` both give.

**Outcome:** `drop_bom()` in `R/check-supplement.R` drops a UTF-8 byte order mark, and `read_lockfile_versions()` and `lock_versions()` both call it, so `write_dockerfile()` reads such a lockfile with no warning. `listed_exactly()` moved beside `lock_source()` and now runs for `renv.lock` too, so `write_dockerfile()` refuses `Renv.lock` with `supplement_error_no_file`, and its hint says "listed under another spelling". A folder that lists nothing counts as listing the part. `check_renv_lock()` gives one `"renv-mismatch"` row before the report rows when a read lockfile's path is listed under another spelling, and `listed_path()` names the listed path (by `fold_case()`, else `fs::path_real()` on a part that is not a link). A path part that is empty, or on Windows holds `\` or ends in a space or `.`, skips that check. `lock_source()` reads `renv/profile` through `profile_line()` also when `RENV_PROFILE` is set, and sets `from = "both"` on a byte-for-byte match, which never changes the pick. `inform_lock_source()` and the name error of `dockerfile_lock_source()` then name both sources. The help, NEWS.md (one sentence on the row), and DESIGN.md describe it. The tests add 6 cases, and `ignores_case()` moved to `helper-files.R`.

**Decisions:** none promoted. The plan chose naming both sources over "renv/profile names it", because the package cannot tell who set the variable. The user chose at the plan gate to add the `check_supplement()` row and to skip the Docker image tests.
