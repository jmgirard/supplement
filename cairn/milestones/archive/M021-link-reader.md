# M021: The link check reads links only from tags

**Status:** done (2026-10-20, PR #22 https://github.com/jmgirard/supplement/pull/22)

**Goal:** `check_supplement()` reads link values only from the start tags of a page, by stated rules for attribute names, values, and character references, so page text gives no `broken-link` row and an encoded link is checked as the file name it names.

**Outcome:** `page_links()` in `R/check-supplement.R` now calls `tag_links()`, which removes comments, `<!…>`/`<?…>` markup, and the text of script, style, textarea, and title (kept start tags; each removed or kept part followed by a space) with one `gsub()` over `html_skipped`, then reads start tags with `gregexpr(html_start_tag)`. Both whole-page calls use `useBytes = TRUE` with `Encoding()` reset to UTF-8, since without it a non-ASCII page took time that grew with the square of the tag count. Every repeat is possessive; a tag may end at the end of the page and is then dropped; tag names use explicit ASCII letter classes (`ascii_any_case()`, `ascii_lower()`), not `(?i)` or `tolower()`. Names `href`, `src`, `xlink:href` match whole in any case; quoted and unquoted values; a value with no `=` is empty. `decode_refs()` decodes five named references and number references (1 to 0x10FFFF, not surrogates or 128 to 159) before trimming, the scheme skip, and `percent_decode()`. A warning from the reader (PCRE match limit) makes `page_links()` return FALSE and gives its own row. The help page states the rules and the cases read differently from a browser; README, the template `_README.md`, NEWS, and DESIGN say so. Tests: one per criterion, plus a 6 MB script page, unclosed markup, 60,000 unclosed `<a `, a 20,000-tag non-ASCII page, and a mocked reader warning.

**Decisions:** D-017 (a base R tag reader, not xml2, chosen at the plan question set). Milestone-local: unquoted values are read; `<!-->` and `<!--->` stay a stated limit, because the Scope Out list stated the `-->` rule.
