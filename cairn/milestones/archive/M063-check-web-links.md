# M063: Check web links on the rendered site

**Status:** done (2026-10-27, PR #64 https://github.com/jmgirard/supplement/pull/64)

**Goal:** `check_supplement(web_links = TRUE)` requests each `http` or `https` address that its tag reader finds on the rendered pages and gives a row for each one that fails, and `release_supplement()` does not run this check.

**Outcome:** `check_supplement()` gained `web_links = FALSE` (D-030). With TRUE, `check_web_links()` in `R/check-supplement.R` takes the addresses from `web_addresses()`: the `http`/`https` values (any letter case, `#` part removed) of the pages `check_links()` reads. The two share `site_pages()` and `page_values()`, the read-decode-trim step split out of `page_links()`. Each address is requested once, in byte order (`order_bytes()`, now under `sort_bytes()`), by `url_status()`: base `curlGetHeaders()` through a NULL namespace binding that tests mock, `redirect = TRUE`, `timeout = 10`, a space sent as `%20`. `web_problem()` gives a `web-link` row for a failed request, a status of 400 or above, or no status (below 100). For 401, 403, 405, and 429 the row says the link can work in a browser. Rows name the first page that links the address. DESCRIPTION has `Depends: R (>= 4.1.0)` (D-031), since `timeout` came in R 4.1.0. Tests mock `url_status()` or `curlGetHeaders`, so no test makes a web request. `?check_supplement`, `?release_supplement`, NEWS.md, README.md, GUIDE.md, the publishing vignette, and DESIGN.md state it.

**Decisions:** D-030 (opt-in, report-only web check), D-031 (R 4.1.0 floor). The plan chose `curlGetHeaders()` HEAD requests over GET or a new package, an argument over a separate exported function, and one row per address over one per page.
