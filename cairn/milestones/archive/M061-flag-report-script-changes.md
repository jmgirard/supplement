# M061: Flag reports after report.R changes

**Status:** done (2026-10-26, PR #62 https://github.com/jmgirard/supplement/pull/62)

**Goal:** `check_supplement()` gives a `"stale-script"` row for each report whose stored output came from other `_scripts/report.R` text than the site holds now, so `release_supplement()` stops before it archives that output.

**Outcome:** `print_environment()` in the template's `_scripts/report.R` ends the Computing environment section with `Shared report code: _scripts/report.R, MD5 <hash>`, the file's MD5 with each CR LF read as LF. A `local()` closure takes the hash when the `site` chunk sources the file, so a report that later sets `site` for its own data still prints it. `check_stale_script()` in `R/check-supplement.R` runs after `check_stale_output()`. `stored_script_hashes()` reads the top-level `result.markdown` of each non-hidden `.json` in `_freeze/analyses/<name>/execute-results/` through the new `stored_json()`, which `stored_hash()` now shares. It finds the text with a fixed-string `gregexpr()` (no PCRE) and keeps the 32 characters after it when they are lowercase hex. A report gets one row when a hash differs from `report_hash()` of the site's file. The row names the differing files in byte order with `quote_path()` and gives `rerender_steps`. When another file holds only matching hashes, the row adds the dropped-format hint and delete steps of `"stale-output"`. No row: no hash line, an unreadable report (a link to a missing file), or a missing, folder, or unreadable `report.R`. The `check_supplement()` and `add_report()` help, GUIDE.md "Shared report code" and "Computing environment", README.md and GUIDE.md check lists, NEWS.md (new bullet; the M058 bullet drops "gives no stale-output row"), and DESIGN.md follow. `analyses/example.qmd` is unchanged, so the `placeholder` row still finds an unedited example.
