# M070: Fill in the demo site

**Status:** done (2026-10-28, PR #71 https://github.com/jmgirard/supplement/pull/71)

**Goal:** Make the package site's demo a finished-looking supplement for a made-up study, built in CI from `create_supplement()` and the package's own functions.

**Outcome:** `.github/scripts/build-demo.R` starts from `create_supplement(<temp folder>, repo = "jmgirard/supplement")`. It adds `participants.csv` and `diary.csv`, simulated by the seeded base R `.github/demo/simulate.R` outside the site, with `add_data()`. It adds three reports (Sample Description, Main Analysis, Robustness Checks) with `add_report()`, and puts each body from `.github/demo/analyses/*.md` in place of the stub's opening paragraph and `setup` chunk. Every text edit goes through `replace_once()`, which reads and writes bytes and stops unless its text occurs exactly once, overlapping copies counted. These edits fill `_supplement.yml` (made-up Rivera and Chen authors, ORCID's example iD, version 1.0.0, DOI `10.5281/zenodo.0000000`, archive link `https://zenodo.org/records/0000000`) and both LICENSE files, and swap the setup box for a note that the content is made up. They also drop the Archived Version instruction and the example entries. `remove_file()` deletes the example report, data file, and figure. The script writes `CITATION.cff` and `.zenodo.json` and renders twice (D-018). It then stops unless `check_supplement()` returns no row and skips exactly the three git checks, and only then copies `docs/`. It turns `~+~` in its own path back into spaces. README, NEWS, DESIGN.md, and the `pkgdown.yaml` step comment describe the new demo.

**Decisions:** D-034 (the demo is a filled-in made-up study built from `create_supplement()` and the package's functions; supersedes D-033's unchanged-render choice). The user chose a built made-up demo over linking a real supplement of theirs, a made-up diary study over a built-in R dataset, and an example DOI that resolves to nothing.
