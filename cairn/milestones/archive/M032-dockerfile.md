# M032: write_dockerfile() writes a container recipe from renv.lock

**Status:** done (2026-10-22, PR #34 https://github.com/jmgirard/supplement/pull/34)

**Goal:** `write_dockerfile()` writes a Dockerfile and a `.dockerignore` from a site's `renv.lock`, so that an author can build an image with the site's R, packages, and Quarto, and render a report in it with the site folder mounted.

**Outcome:** `R/write-dockerfile.R` exports `write_dockerfile(path = ".", quarto, digest = NULL, overwrite = FALSE)`. It reads `R.Version` and `Packages.renv.Version` from `renv.lock` with jsonlite, refuses R before 4.0.0 and renv before 1.3.1, and refuses a link or folder at either target even with `overwrite = TRUE`, all before any write. It writes `.dockerignore` (`*`, `!renv.lock`), then a Dockerfile: `FROM rocker/r-ver:<R>[@<digest>]`; `RENV_PATHS_LIBRARY=/opt/renv/library` and `RENV_CONFIG_CACHE_ENABLED=FALSE`; `/rocker_scripts/install_quarto.sh <quarto>`; `COPY renv.lock`; one RUN that installs the lockfile's renv from p3m.dev's CRAN archive into a temporary `R_LIBS`, writes the apt packages of `renv::sysreqs()` to a file for `xargs -r apt-get install` (noninteractive), and runs `renv::restore(library = renv::paths$library())`; `WORKDIR /site`. Both files are LF. Classes: argument, no_file, lockfile, file_exists, write. The help and the guide part "Running reports in a container" show the build, an offline render as the user with the site mounted at `/site`, the digest read with `docker buildx imagetools inspect`, `docker save`, and what Zenodo keeps. README has a "Record the R setup" part; one NEWS bullet. `test-write-dockerfile.R` holds byte, version-source, digest, refusal, call, and link tests, and one Docker build-and-render test gated by `SUPPLEMENT_TEST_DOCKER=true`, which CI does not set.

**Decisions:** milestone-local: renv before 1.3.1 is refused, because its `sysreqs()` does not read the lockfile's packages; a fixed bootstrap renv was not taken, since its library path could differ from an older `activate.R`'s. The renv cache is turned off rather than only its links (72 MB less in the image). No D-entry.
