# M026: check_supplement() finds code of any engine and more inline shapes

**Status:** done (2026-10-20, PR #27 https://github.com/jmgirard/supplement/pull/27)

**Goal:** `check_supplement()` gives a `no-stored-output` row for reports whose only code is a chunk of another engine, `r#` or `{r}` inline code, or code in a file that holds a nul byte.

**Outcome:** In `R/check-supplement.R`, `chunk_start` is now Quarto 1.10.19's chunk scan (`languagesWithClasses()`) with a lookahead that leaves out a whole `ojs`, `mermaid`, or `dot` name in any letter case, so `{bash}`, `{sql}`, `{Rcpp}`, `{rust}`, and any other name count. `inline_r` adds `` `r#code` `` and `` `{r} code` `` under `engine: knitr`. The new `read_report_lines()` reads the report as bytes inside one `tryCatch()`, maps each nul to 0x01 (a nul inside the braces keeps a chunk start, one before the backticks or after `}` ends it, as in Quarto), and splits at LF, CR LF, or CR. Tests add one report per shape, including seven nul and line-end reports, and turn the M024 `{rust}`, `{Rcpp}`, and `r#` no-row cases into rows. The help item states the rules and limits (one-line inline code, only the report's own top-level `engine: knitr`, chunks under `engine: markdown`, Quarto's wider white space, a tab after `{r}`), and the NEWS.md `check_supplement()` bullet was edited. T1 probes and a read of `markdownExecutionEngine()` confirmed which names start an engine.

**Decisions:** AC4 amended once (substantive): the planned "drops each nul byte" rule would report `{r}<NUL>`, which Quarto never runs. After two re-audits the user chose the text that reads a nul as none of the code rule's named characters, with seven listed reports. No D-entry.
