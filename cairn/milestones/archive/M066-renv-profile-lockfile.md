# M066: Read the lockfile of the active renv profile

**Status:** done (2026-10-27, PR #67 https://github.com/jmgirard/supplement/pull/67)

**Goal:** With `renv_lock = TRUE`, `check_supplement()` compares the stored output of each report with the lockfile of the renv profile that renv picks for the site.

**Outcome:** `lock_source()` in `R/check-supplement.R` applies renv 1.3.1's rule: the session's `RENV_PROFILE` when it is not empty, else the first line of `renv/profile`, untrimmed, with `default` or an empty name meaning no profile. A profile's lockfile is `renv/profiles/<name>/renv.lock`, the name joined as given. `lock_versions()` takes that path, and a path Windows cannot convert counts as unreadable. `check_renv_lock()` prints a "Picked" message naming the lockfile, the profile, and its source. The renv-mismatch and renv-missing rows, the unreadable-lockfile row, and the skip message name the lockfile through `show_text()`, and the rows add "with the renv profile "<name>" active" to the renv steps. A `renv/profile` that is a folder or cannot be opened gets one row of its own. `RENV_PATHS_LOCKFILE` and `RENV_PATHS_RENV` are not read. The help, NEWS.md, README.md, the publishing vignette, GUIDE.md, and DESIGN.md describe the rule. Tests cover 12 profile cases, exact rows and messages for `dev` and `a{b} c`, a missing profile lockfile, an unreadable `renv/profile`, and a name that is not UTF-8.

**Decisions:** none promoted. The user chose to follow the active profile at the plan, over a lockfile path in `renv_lock`. The plan chose base R over `renv::paths$lockfile()`, which reads `RENV_PROFILE` alone.
