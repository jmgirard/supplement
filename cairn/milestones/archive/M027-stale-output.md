# M027: check_supplement() finds stored output older than its report

**Status:** done (2026-10-21, PR #28 https://github.com/jmgirard/supplement/pull/28)

**Goal:** `check_supplement()` gives a `stale-output` row for a report whose stored output in `_freeze/` was made from other text than the report holds now.

**Outcome:** New `check_stale_output()` in `R/check-supplement.R`, called after `check_stored_output()`, which now shares the report list through `analysis_reports()`. For each `.qmd` directly in `analyses/` with stored output, `report_hash()` takes the MD5 of the report's bytes with each CR LF read as LF (through a temp file and `tools::md5sum()`), and `stored_hash()` reads the top-level `hash` of each `.json` in `execute-results/` (not hidden, not a folder) with `jsonlite::parse_json()`. A differing hash gives one row, and a file that does not parse, has a non-object top level, or has no single text `hash` gives one row with the "cannot be read" text, which wins. An unreadable report gives no row. Both texts say to render the report by name and commit `_freeze/`. The rows stop `release_supplement()` with no change there. The help item states the rules and the limits: Quarto 1.10.19 hashes only the report file (T1 probe: includes, `_quarto.yml`, and `_metadata.yml` do not count), bad UTF-8 bytes are hashed as U+FFFD, and a dropped format's `.json` keeps its old hash. NEWS.md, README.md, and the template README name the check. Tests: AC1 and AC2 fixture reports, a Quarto test of full and by-name renders (CR LF, an include), and a release test that runs the real check; `local_plain_git()` and `git_site()` moved to `helper-template.R`.

**Decisions:** none. The plan gate chose the stored hash over file times, because git keeps no file times.
