# M060: Tighten the missing report.R check

**Status:** done (2026-10-26, PR #61 https://github.com/jmgirard/supplement/pull/61)

**Goal:** The `"missing-script"` row of `check_supplement()` counts a report line as naming `_scripts/report.R` only when one of the AC1 forms joins the two names, and it treats a file link to a missing file as missing on every system.

**Outcome:** `names_script()` in `R/check-supplement.R` is one PCRE `grepl()` pattern with no `.*` between the names: `_scripts` with no ASCII letter, digit, `_`, or `.` before it, then `/`, `\`, or `\\`, or an optional such run and a quote, a comma with spaces or tabs, and a quote, then `report.R` with none of those after it. Each boundary `_scripts` can start the match, and a `.` after `report.R` stops it. `check_missing_script()` also counts the file as missing when `is_link()` is TRUE and the new `link_ends_on_file()` is FALSE. That helper expands `~` with `path.expand()`, resolves the chain with `fs_path_real()` (a wrapper of `fs::path_real()`), and counts any error, a folder, or a missing target as no file; a path that is not valid UTF-8 keeps the `file.exists()` answer. `fs::is_file()` was dropped because it never returns on a link to a link (fs 2.1.0). The help page states the rule, the `.` stop, and the link cases, and no longer states the Windows limit. Tests: 7 row lines, 5 no-row lines, 5 MB lines first and last and a 5 MB run of spaces and tabs, links to a missing file, an existing file, and a link, a loop, a mocked fs error, and a non-UTF-8 path. The link tests no longer skip on Windows. DESIGN.md's missing-script lines describe the pattern and the helper. No NEWS change: the unreleased M059 bullet stays true.

**Decisions:** none promoted. The plan chose the separator rule at the user's choice, and `fs::path_real()` replaced `fs::is_file()` at review return 1.
